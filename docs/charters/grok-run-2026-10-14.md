## How an item closes

Every item closes in exactly one of these four ways:

1. **Already fixed.** A commit in `51bd074..HEAD` already fixed it, and a test covers it. Record
   the SHA on the Board. No Cycle needed.
2. **Real.** Write a test that fails for the stated reason, fix it, and see the test pass. Commit
   both together.
3. **False positive.** Write a test that pins the correct behaviour the finding doubted, and commit
   the test. Mark it false positive on the Board with one line on why.
4. **Too big for one Cycle.** Split it on the Board. The slices keep this item's rank.

Invariants for every item, unless the item says otherwise:
- Change only the function or module the finding cites, plus its test.
- Every existing test stays green and unedited. If an existing test pins the wrong behaviour,
  update that assertion and say so in the commit message. Don't delete it.
- No new `skip`, `only`, `eslint-disable`, `@ts-ignore`, raised timeout or lowered threshold.
- Copy rules: an error state says what failed. Never report success for something the gateway
  did not confirm.

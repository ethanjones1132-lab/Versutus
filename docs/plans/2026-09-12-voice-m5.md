# Milestone M5 — Local voice on this PC (the flagship)

Expansion of the M5 rows of `docs/plans/2026-09-12-realtime-voice-plan.md` §M5 into the
Phase 0 TDD step format (failing test → run → implement → run → commit). The plan fixes
the contracts, files and acceptance; this document fixes the steps, code and commands.

Inputs:
- M1 `docs/plans/voice-spikes/DECISIONS.md`: `local` is the flagship; `codex` is
  disabled; `auto` resolves `local` → `phone`.
- M1 `docs/plans/voice-spikes/s2-findings.md` and `gate/voice-worker/models.lock.json`:
  the measured model versions, URLs, SHA-256s and the pass/fail timings.
- M2 landed the Gate media socket, the call-loop reducer and the turn runner.
- M4 landed the engine choice and the app's `transport: 'gate'` branch. The branch is
  unreachable until this milestone makes `local` report `ready`.

Rules carried from Phase 0:
- `npm run verify` must exit 0 before every commit.
- Kotlin is untouched; no Gradle step.
- No live Gate, Hermes, OpenClaw or `opencode` process is started. The worker is spawned
  only by its own tests, with fakes.
- No model is downloaded during `npm run verify`; tests use synthetic audio and fakes.
- Device-only acceptance (three turns foreground/background/locked, LAN latency) is
  PENDING-DEVICE. `voice doctor` on this PC is PENDING-HOST if a model cannot be fetched.
- Never weaken a test to pass it.

Architecture this milestone fixes:
- **The worker** is a Python package, `gate/voice-worker/versutus_voice/`, run from a
  uv venv at `%LOCALAPPDATA%\Versutus\Gate\voice\venv` (`resolveGateHome()`,
  `gate/core/paths.mjs:3`). One worker, warm models, newline-delimited JSON-RPC over
  stdio through `createStdioJsonRpc` (`gate/core/cli-environments/jsonrpc-stdio.mjs:8`).
- **The engine** is `gate/core/voice/engines/local-engine.mjs`, an `EventEmitter`
  implementing the §4.5 interface. It is the only process that runs speech models.
- **The Gate** keeps the call loop pure: `gate/core/voice/voice-session.mjs` drives the
  engine and `runBackendTurn` (`gate/core/voice/turn-runner.mjs`), exactly as the typed
  chat route does, so a spoken turn and a typed turn pin the same model.

**Design — the worker RPC (newline-delimited JSON-RPC, one object per line):**

Client → worker requests:
| method | params | result |
|---|---|---|
| `voice.describe` | `{}` | `{ ok: true, sampleRate: { input, output } }` |
| `voice.open` | `{ voiceSessionId, botName }` | `{ ok: true }` |
| `voice.pushAudio` | `{ chunk: { data, sampleRate, numChannels } }` | `{ ok: true }` |
| `voice.speak` | `{ gen, text, final }` | `{ ok: true }` |
| `voice.cancelSpeech` | `{ gen }` | `{ ok: true }` |
| `voice.setMuted` | `{ muted }` | `{ ok: true }` |
| `voice.close` | `{}` | `{ ok: true }` |

Worker → client notifications:
`voice.partial {text}` · `voice.final {text}` · `voice.speechAudio {gen, chunk}` ·
`voice.speechDone {gen}` · `voice.error {code, message, fatal}`.

Audio chunks always use Codex's `ThreadRealtimeAudioChunk` shape
`{ data: <base64>, sampleRate, numChannels }` (§4.6), so `local` and `codex` share one
internal type. Input is 16 kHz mono PCM16LE; output is 24 kHz mono PCM16LE.

    from 16 kHz to 24 kHz keeps the frequency within 1 % and the length in tolerance;

**Runtime contract:**
- `voicePaths(env, platform)` → `{ home, venv, python, models, worker, lockFile }` under
  `resolveGateHome(env, platform)` (`gate/core/paths.mjs:3`), per §4.6.
- `fetchVerified({ url, sha256, dest, fetchImpl, fsImpl })` → downloads to `dest.part`,

  {state,reason}, codex } }`; feeds `voice.capabilities`.
- `voiceDoctor({ paths, runUv, spawnSync, log })` → checks the venv, CUDA device count
  and free VRAM, loads every model, then a two-second Kokoro→Whisper round trip and

**Design:** `LocalEngine extends EventEmitter` implements the §4.5 interface. It is
constructed with injected seams — `{ spawn = spawnVoiceWorker, rpc = createStdioJsonRpc,
backoffMs = [250, 500, 1000, 2000], maxRestarts = 5, paths }` — so node:test drives it
with a fake child. `open()` ensures the worker is up and sends `voice.open`; `pushAudio`
base64-encodes the frame and sends `voice.pushAudio`; worker `voice.partial`/`voice.final`/
`voice.speechAudio`/`voice.speechDone`/`voice.error` notifications re-emit the engine
events. A child `exit` starts the backoff restart; after `maxRestarts` it emits a fatal
`error` and the call ends with the existing `engine-error` path. `close()` sends
`voice.close` and kills the child.

## Task 5.4 — Pipeline wiring: the reducer drives the local engine

**Files:** modify `gate/core/voice/media-socket.mjs` and `gate/core/voice/voice-session.mjs`;
modify `gate/core/server.mjs`; tests `gate/__tests__/voice-local-pipeline.test.mjs`
and a pytest end-to-end (`gate/voice-worker/tests/test_pipeline.py`).

**Design:** the media socket stops relaying engine events straight to the phone. It
constructs `reduceVoiceSession` per call and runs each effect:
`engine.speak` → `engine.speak`; `engine.cancelSpeech` → `engine.cancelSpeech`;
`turn.run` → `runBackendTurn(backend, sessionId, { text, model },
{ onDelta: replyDelta, onToolCall, onApproval: approvalRequired, signal })`;
`send` → the phone frame; `sendAudio` → the binary frame; `audit` → the M9 sink
(no-op here). Engine `partial`/`final`/`handoff`/`speechAudio`/`speechDone`/`error` and
phone `mute`/`skip`/`bargein`/`end` all become reducer events. `turn done` sends the
phone's `turn done` frame so the app reloads history (§4.5).

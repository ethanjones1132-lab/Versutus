## Task 6.1 — VAD-confirmed barge-in on the Gate

Today only the phone's `bargein` frame cancels speech. A `local` call must also interrupt
when the operator starts talking without touching the screen. §4.6 step 5: VAD speech for
≥ 250 ms during `speaking`, or the phone's `bargein` frame → cancel the speech generation
and return to `listening`; the reply stays in history.

- [ ] **Step 1: Write the failing tests.**
  - pytest (`test_pipeline.py`): while a generation is being spoken (a fake synthesizer
    that yields chunk by chunk), pushing a 500 ms tone makes `pushAudio` emit
    `voice.userSpeechStart` exactly once for that utterance, and `speak` stops yielding
    further chunks. A tone while listening does not emit it.
  - node (`voice-local-pipeline.test.mjs`): the fake engine emits `userSpeechStart` during
    `speaking` → the socket cancels that generation (`engine.cancelled` holds the live
    gen) and sends `phase: listening`; a `userSpeechStart` while `listening` is inert.
- [ ] **Step 2: Run to confirm they fail.**
  `node gate/voice-worker/run-tests.mjs` and
  `cd gate; node --test "__tests__/voice-local-pipeline.test.mjs"`.
- [ ] **Step 3: Implement in the worker.** `VoicePipeline` tracks a `speaking` flag set by
  `speak` and cleared by `speechDone`/`cancelSpeech`; a VAD `speech_start` while speaking
  emits `voice.userSpeechStart` and cancels the current generation (set a cancelled gen so
  the generator stops). Keep the 32 ms-window path, so confirmation lands inside the
  plan's 150 ms Gate-side budget.
- [ ] **Step 4: Map it in the engine and socket.** `LocalEngine._onNotification` maps
  `voice.userSpeechStart` → `emit('userSpeechStart')`. `media-socket.mjs` dispatches
  `{ type: 'bargein' }` on `engine.on('userSpeechStart')`; the reducer already cancels the
  live generation and reopens `listening`.
- [ ] **Step 5: Run** — pytest and `node --test` PASS.
- [ ] **Step 6: The gate and commit.** `npm run verify` EXIT=0, then:

```bash
git add gate/voice-worker/versutus_voice gate/voice-worker/tests gate/core/voice/engines/local-engine.mjs gate/core/voice/media-socket.mjs gate/__tests__/voice-local-pipeline.test.mjs gate/__tests__/voice-local-engine.test.mjs
git commit -m "feat(voice): starting to talk interrupts the PC voice without touching the phone"
```

## Task 6.3 — Speculative turns on the local engine

§M6: start the Bot turn on a high-confidence early end of turn, and cancel it through the
turn runner's abort signal if speech resumes within 600 ms.

- [ ] **Step 1: Write the failing node test** (`voice-local-pipeline.test.mjs`): with a
  `runTurn` that records its `signal`, a `speculative` start runs the turn; a
  `userSpeechStart` within 600 ms aborts that signal and the turn is discarded (no `reply`
  frame, no `turn done`); if the operator stays quiet past 600 ms, the eventual `final`
  promotes the already-running turn instead of starting a second one.
- [ ] **Step 2: Run to confirm it fails.**
  `cd gate; node --test "__tests__/voice-local-pipeline.test.mjs"`.
- [ ] **Step 3: Implement in the socket.** Track `speculative = { gen, controller,
  timer }`; on a high-confidence early end-of-turn event from the engine (a new
  `earlyEnd` event the worker emits when Smart Turn is confident before the forced
  completion) start the turn and set a 600 ms timer; `userSpeechStart` before the timer
  fires aborts and clears it; `final` clears the timer and keeps the turn. No reducer
  phase changes: the reducer keeps `listening` until `final`, so a discarded speculation
  leaves no trace.
- [ ] **Step 4: Run** — PASS.
- [ ] **Step 5: The gate and commit.** `npm run verify` EXIT=0, then:

```bash
git add gate/core/voice/media-socket.mjs gate/core/voice/engines/local-engine.mjs gate/voice-worker/versutus_voice gate/__tests__/voice-local-pipeline.test.mjs
git commit -m "feat(voice): the PC can think about a reply before the operator has finished"
```

## Task 6.5 — The latency harness and its baseline

§M6: `scripts/voice-spikes/latency-harness.mjs` drives a call as a Node WebSocket client
sending fixture PCM. It reports p50 and p95 of end of speech → first audio, per engine, on
LAN and on cellular Tailscale, and fails against a stored baseline on regression.

- [ ] **Step 1: Write the failing node:test**
  (`scripts/__tests__/voice-latency-harness.test.mjs`): `percentile(values, p)` is exact
  on a known series; `compareToBaseline({ p50, p95 }, baseline, tolerance)` passes within
  tolerance and fails (`{ regressed: true }`) when p95 exceeds it; the harness's sum-type
  input (a list of `{ endOfSpeechAt, firstAudioAt }`) turns into the two numbers.
- [ ] **Step 2: Run to confirm it fails.**
  `cd gate; node --test "../scripts/__tests__/voice-latency-harness.test.mjs"`.

  the accepted baseline at `docs/plans/voice-spikes/latency-baseline.json`; `--check`
  exits nonzero on regression.

# Milestone M7 — Reliability

Expansion of the M7 rows of `docs/plans/2026-09-12-realtime-voice-plan.md` §M7 into the
Phase 0 TDD step format (failing test → run → implement → run → commit). The plan fixes the
contracts; this document fixes the steps, code and commands.

Inputs:
- M5 task 5.3 already supervises the worker (`LocalEngine` restarts with backoff and re-opens
  the session). M7 proves the *call* survives that restart.
- M2/M5 built the media socket as one closure per connection; a dropped socket ends the call
  today. M7 turns that closure into a per-session call the socket can re-attach to.

## Task 7.1 — The Gate keeps a dropped call for 20 s

§4.5: the phone reconnects with its `voiceSessionId` within 20 s. The Gate keeps the call:
listening state, the turn in flight continues, up to 5 s of speech buffered. After 20 s the
call ends with reason `network`.

- [ ] **Step 1: Write the failing test.** `gate/__tests__/voice-resume.test.mjs`:
  a first socket connects, reaches `ready` and hears a `final`; it closes (a network drop).
  The engine then emits `speechAudio` while no socket is attached; a second socket with the
  same session id and token re-attaches and receives `ready`, the live `phase`, and the
  buffered binary frame. No `ended` frame was sent and the engine was not closed. A second
  test with `resumeTimeoutMs: 80` never re-attaches: after the timeout the registry session
  is `ended` and the engine is closed. The media socket is started with an injectable
  `resumeTimeoutMs` and `endAll()`.
- [ ] **Step 2: Run to confirm it fails.**
  `cd gate; node --test "__tests__/voice-resume.test.mjs"`.
- [ ] **Step 3: Implement the per-session call.** In `media-socket.mjs`, move the per-call
  closure state (`engine`, `call`, `turnAbort`, `speculative`, `timer`, `sendFrame`) into a
  `Call` keyed by `voiceSessionId` in a `Map`. `attach(ws)` binds the socket, clears the
  resume timer, re-sends `ready` + the current `phase`, then flushes the buffer. `detach()`
  on close/error clears the no-audio timer and starts `resumeTimeoutMs` (default 20 s); when
  it fires it dispatches `socketClosed` (→ `ended` reason `network`). While detached,
  outbound frames are buffered in order, with audio capped to `audioBufferMs` (default 5 s
  at 24 kHz). A re-attach for a live session resumes the same `Call`.
- [ ] **Step 4: Run** — PASS.
- [ ] **Step 5: The gate and commit.** `npm run verify` EXIT=0, then:

```bash
git add gate/core/voice/media-socket.mjs gate/__tests__/voice-resume.test.mjs
git commit -m "feat(voice): a dropped call is held for the phone to rejoin"
```

## Task 7.2 — A Gate shutdown ends calls with a named reason

§M7: a Gate restart mid-call is a clean end with a named reason.

- [ ] **Step 1: Write the failing test** (in `voice-resume.test.mjs`): with a socket open and
  `ready`, `media.endAll('gate-restart')` sends that socket an `ended` frame with reason
  `gate-restart` exactly once, closes the engine, and marks the registry session ended.
- [ ] **Step 2: Run to confirm it fails.**
  `cd gate; node --test "__tests__/voice-resume.test.mjs"`.
- [ ] **Step 3: Implement.** Add `endAll(reason)` to the object returned by
  `attachVoiceMediaSocket`: for each live `Call`, end it with the reason and close its
  socket, then clear the map. In `server.mjs`'s `gateObj.close()`, call
  `voiceMedia.endAll('gate-restart')` before `voiceMedia.close()`, so a restart is a clean,
  named end rather than a silent drop.
- [ ] **Step 4: Run** — PASS.
- [ ] **Step 5: The gate and commit.** `npm run verify` EXIT=0, then:

```bash
git add gate/core/voice/media-socket.mjs gate/core/server.mjs gate/__tests__/voice-resume.test.mjs
git commit -m "feat(voice): stopping the Gate ends a call cleanly instead of dropping it"
```

## Task 7.3 — A worker crash does not kill the call

M5 task 5.3 restarts the worker with backoff. Pin that the *next* frame after a restart
reaches the new worker, so a mid-call crash is invisible to the phone.

- [ ] **Step 1: Write the failing test** (`gate/__tests__/voice-local-engine.test.mjs`): after
  the first child exits and the scheduled restart runs, `engine.pushAudio(frame)` is written
  to the second child's stdin, and the call has no fatal `error`.
- [ ] **Step 2: Run to confirm it fails.**
  `cd gate; node --test "__tests__/voice-local-engine.test.mjs"`.
- [ ] **Step 3: Fix only if the pin fails.** No production change is expected (5.3 already
  re-opens the session); if it fails, the defect is in `_ensureWorker`/`pushAudio`.
- [ ] **Step 4: Run** — PASS.

```bash
git add gate/__tests__/voice-local-engine.test.mjs
```

## Task 7.4 — The app offers unsent speech after a network end

Existing `reduceGateCall` holds the last `final` as `recovery` and never sends it. Pin the
network path: a `network` end keeps the recovery text and raises one `ended` effect.

- [ ] **Step 1: Write the failing test** (`__tests__/gate-call-test.ts`): feed `final` then
  `ended` with reason `network`; assert `recovery` is the final text, `endedReason` is
